## Using it

```tsx
// app entry, once
import '@reach/ui/styles.css';

// anywhere
import { Button, Field, FieldControl, FieldLabel, Input } from '@reach/ui';
```

The package still publishes under its original name while the rename works its way through the
services, so the import path lags the brand for now.

What ships is TypeScript source rather than build output. Next.js compiles it through
`transpilePackages` and Vite compiles it directly, which means editing a component shows up in the
canvas with no build step in between.

## What it stays out of

The system is presentation only. It imports no contract, no domain type and no data client, so one
module's concepts cannot leak into another module's screens. You will not find a page shell,
navigation or data fetching here. A module owns its screens. Reach owns the vocabulary those
screens are written in.

## Four toolbars, and why they matter

Theme, viewport, platform and density all write to `<html>`, which is exactly what an application
does. Switch **platform** to Television and the whole system scales by 1.5, controls grow to 52px
and the focus ring gains a halo, because on a TV the focus ring _is_ the cursor. None of it is a
Storybook-only mechanism.

## Four rules that settle most arguments

1. **Semantic tokens only.** Components consume `bg-surface`, never `bg-neutral-100`. Renaming a
   primitive costs nothing. Renaming a semantic token is a breaking change.
2. **Colour is never the only signal.** Roughly one man in twelve cannot separate the success and
   danger washes, so the label has to carry the meaning on its own.
3. **Money is never a float.** Minor units in, exact string formatting out. `Number()` loses cents
   at the fifteenth digit, and payroll does not tolerate rounding.
4. **Density follows the pointer, not the screen.** A `size="md"` control is 36px under a mouse and
   44px under a thumb. The input device changed, not the window width.
